# 双色球 / 大乐透 开奖号码筛选器

一个本地运行的网页应用：自动从官方渠道抓取开奖数据，按你的要求筛选、统计号码，并生成胆拖 / 复式投注方案。

## 一、怎么用

1. 双击 **`启动服务.cmd`**（或 `start.cmd`）。
2. 窗口里会打印两个网址：
   - **电脑访问**：`http://localhost:8788`
   - **手机访问**：`http://<你电脑的局域网IP>:8788`（手机需与电脑连同一个 Wi-Fi）
3. 浏览器打开即可使用。**这个黑窗口不要关**，关掉就等于停止服务。

> 没有 Node.js 的话，先去 https://nodejs.org/zh-cn 装一个（装完重开窗口即可）。

## 二、功能

顶部可切换彩种：**双色球** / **大乐透**；每个彩种下有 3 个标签页。

| 标签页 | 内容 | 期数可选 |
| --- | --- | --- |
| 历史开奖号码 | 最近 N 期，**走势图格式**（期号/星期/分区号码走势 + 和值/跨度/区间比/奇偶比 + 四行统计） | 默认 50 期，50→100 步进 10 |
| 历史同期 | 与最新一期**期号相同**的历史各年同号期（如第 116 期），走势图格式；下方带号码池、胆拖、复式功能 | 默认 10 期，10→100 步进 5 |
| 每周同期 | 按开奖星期筛选（双色球：周二/周四/周日；大乐透：周一/周三/周六），走势图格式 | 默认 50 期，50→100 步进 10 |


**历史同期页里的四个工具：**

- **号码池**：显示每个号码在这批同期号码中的出现次数与出现率（条形图）。点击号码循环切换 `参与 → 排除 → 胆码`。
  - 红球/前区：三态循环；蓝球/后区：点击即排除 / 恢复。
- **胆拖选号结果**：胆码取自号码池中标记为「胆码」的号，拖码手动填写（或点「取号码池未排除号」）。
  - 注数 = C(拖码个数, 每注需补的个数) × 后区组合数
- **复式选号结果**：前区/红球复式号 + 后区/蓝球（取自号码池未排除号）。
  - 注数 = C(前区个数, 前区选号数) × C(后区个数, 后区选号数)
- 金额统一按 **2 元/注** 计算。

## 三、数据来源与刷新

| 彩种 | 数据源 | 覆盖 |
| --- | --- | --- |
| 双色球 | 中国福利彩票官网（www.cwl.gov.cn）+ 历史开奖库补齐早期数据 | 2003 年至今 |
| 大乐透 | 中国体育彩票官网（webapi.sporttery.cn） | 2007 年至今 |

- 首次打开页面会自动抓取全部历史数据（约 10~30 秒），之后走本地缓存（`data/` 目录）。
- 缓存有效期 6 小时，也可以随时点页面右上角 **「刷新数据」** 强制更新。
- 抓取失败时会自动回退到本地缓存，保证页面仍可用。

## 四、目录结构

```
ssq-dlt-filter/
├─ 启动服务.cmd / start.cmd   一键启动
├─ server.js                  服务端：抓取数据、缓存、提供接口、托管页面
├─ public/
│  ├─ index.html              页面结构
│  ├─ style.css               样式（自适应手机/电脑，支持深色模式）
│  └─ app.js                  前端逻辑：切页、筛选、号码池、胆拖、复式
└─ data/                      自动生成的数据缓存
```

服务端仅使用 Node.js 内置模块，**无需 npm install、无任何第三方依赖**。

| `GET /api/draws?game=ssq\|dlt` | 返回全部历史开奖数据（含缓存标记） |

## 六、说明

- 开奖数据仅供参考，最终以官方公布为准。
- 本工具只做号码筛选与组合展开，**不预测开奖结果**；每注中奖概率相同。
## 七、手机打不开怎么办

1. **确认同一网络**：手机和电脑必须连同一个 Wi-Fi（或同一个路由器）。
2. **Windows 防火墙可能拦截**：右键开始菜单 → 选「终端(管理员)」或「PowerShell(管理员)」，执行一次：
   ```
   netsh advfirewall firewall add rule name="SSQ-DLT-Filter 8788" dir=in action=allow protocol=TCP localport=8788
   ```
   然后重新用手机访问。（第一次运行 `启动服务.cmd` 时如果弹出"是否允许网络访问"，点「允许」也可以。）
3. **IP 变了**：换网络或路由器重启后电脑 IP 可能变化，重新运行启动脚本，以窗口里打印的新「手机访问」地址为准。
4. **端口被占用**：服务会自动改用 8789、8790…，同样以窗口打印的地址为准。

## 八、放到公网（可选）

现在是本地服务，只能在家里/办公室的局域网内访问。若想让手机在任何网络下都能打开，需要把 `server.js` 部署到一台公网服务器（或支持 Node 的云主机 / 容器平台）：
把整个目录上传后在服务器上执行 `node server.js`，再把公网域名或 IP 分享出去即可（可配合 Nginx 反向代理与 HTTPS）。服务端无第三方依赖，部署很简单。
## 九、表格格式（走势图口径）

三个标签页统一使用**走势图格式**显示：

| 期号 | 星期 | 一区 | 二区 | 三区 | 蓝球/后区 | 和值 | 跨度 | 区间比 | 奇偶比 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 开出该号 → 显示号码；未开出 → 显示**遗漏期数**
- 每个标签页下方都有四行统计：出现总次数 / 平均遗漏值 / 最大遗漏值 / 最大连出数
- 遗漏按**当前页面的号码序列**连续计算：
  - 历史开奖号码：按全部开奖期连续计算（与新浪基本走势图一致）
  - 每周同期：按该星期的历史开奖序列连续计算（如所有「周二」开奖）
  - 历史同期：按同一期号的历史序列连续计算（如历年「第 116 期」）

> 注：官网的金额类字段（奖池奖金、一等奖/二等奖注数奖金、销售额、开奖公告链接）仍然完整抓取并保存在 `data/` 缓存与 `/api/draws` 接口里，只是当前表格不再展示。需要的话可以加回表格或做成可切换视图。

## 十、走势图显示细节

走势图显示口径对齐 sina 走势图（`lotto.sina.cn`），已逐格核验一致。

**表头**：期号 | 星期 | 一区 | 二区 | 三区 | 蓝球/后区 | 和值 | 跨度 | 区间比 | 奇偶比

- 双色球分区：01-11 / 12-22 / 23-33，蓝球 01-16
- 大乐透分区：01-12 / 13-24 / 25-35，后区 01-12
- 行序：**旧 → 新**（最新一期在最下面），与新浪一致

**单元格规则**

- 开出该号：直接显示号码（红/蓝区分颜色）
- 未开出：显示**遗漏期数**（不是窗口内从 0 开始，而是**从全部历史延续计算**，与新浪完全一致）

**底部四行统计**（口径与新浪相同）

| 统计行 | 计算方式 |
| --- | --- |
| 出现总次数 | 该号在当前显示的 N 期里出现的次数 |
| 平均遗漏值 | round((N − 出现次数) / (出现次数 + 1)) |
| 最大遗漏值 | 这 N 期里遗漏计数器的最大值（含窗口之前延续下来的值） |
| 最大连出数 | 最大连续开出期数；不足 2 期记为 0 |

> 期号说明：走势图格式下期号统一使用 7 位（如大乐透 `2026066`），与新浪走势图一致。如需改成体彩官网的 5 位格式（`26115`），可随时调整。

## 十二、部署到公网（方案 B：纯静态 + 定时自动更新）

本目录已经是一个**可以直接发布的静态站点仓库**：本地服务只是抓数据的工具，发布后完全用不到它。

### 目录说明

| 路径 | 作用 |
| --- | --- |
| `public/` | 页面文件（index.html / style.css / app.js） |
| `data/` | 开奖数据 JSON（由定时任务更新，前端直接读取） |
| `_site/` | 构建产物（`node build-static.js` 生成，已加入 .gitignore） |
| `build-static.js` | 构建脚本：把 `public/` + `data/` 组装成 `_site/` |
| `.github/workflows/update-and-deploy.yml` | 定时抓数据 + 自动发布到 GitHub Pages |
| `server.js` | 本地服务（实时抓官网）；`node server.js --sync` 只抓数据 |

### 发布到 GitHub Pages

1. 登录 GitHub → **New repository** 新建仓库（选 **Public**），名字随意，例如 `lotto-trend`，**不要**勾选任何初始化文件。
2. 在本目录执行（把用户名和仓库名换成自己的）：
   ```
   git remote add origin https://github.com/你的用户名/lotto-trend.git
   git push -u origin main
   ```
3. 仓库 **Settings → Pages → Source** 选 **GitHub Actions**。
4. 仓库 **Actions → 更新开奖数据并部署 → Run workflow** 手动跑一次。
5. 完成后访问（手机 4G / 任何网络均可）：
   ```
   https://你的用户名.github.io/lotto-trend/
   ```

### 数据如何更新

- **自动**：每天北京时间 21:40、22:40、次日 10:00 各抓一次；有新数据就自动提交并重新发布
- **手动**：Actions 页面点 **Run workflow**
- **本地更新后推送**：`node server.js --sync` → `git add data && git commit -m "更新开奖数据" && git push`

### 如果 Actions 抓不到数据

GitHub 服务器在境外，访问福彩/体彩官网可能超时。workflow 已设置「抓取失败也继续部署」，站点不会挂，只是数据不刷新。此时在本地执行：

```
node server.js --sync
git add data && git commit -m "更新开奖数据" && git push
```

推送后 Actions 会自动重新发布，数据照样更新。

### 换其它免费平台

`_site/` 就是完整站点，任何静态托管都能用：

| 平台 | 构建命令 | 输出目录 |
| --- | --- | --- |
| **Cloudflare Pages**（国内速度较好，推荐） | `node build-static.js` | `_site` |
| Netlify | `node build-static.js` | `_site` |
| Vercel | `node build-static.js` | `_site` |
| 任意静态空间 / 对象存储（OSS/COS） | 本地跑 `node build-static.js`，上传 `_site/` 内全部文件 | — |

> 国内访问 GitHub Pages 有时较慢；如果打开速度不理想，用 Cloudflare Pages 连同一个仓库即可（数据更新照样自动同步）。

### 两种模式的区别

| | 本地服务模式 | 纯静态模式 |
| --- | --- | --- |
| 启动方式 | `启动服务.cmd` | 托管平台自动运行 |
| 数据来源 | 实时抓官网（`/api/draws`） | 读 `data/*.json`（定时更新） |
| 电脑关机 | 手机无法访问 | 照常访问 |
| 手机在外网 | 需内网穿透 | 直接可用 |
| 页面表现 | 状态栏显示「本地缓存 / 刚刚更新」 | 状态栏显示「静态数据」，「刷新数据」变为「重新加载数据」 |

前端会**自动判断**：能连上后端就用实时接口，连不上就自动读静态 JSON，两套模式共用同一份代码。
